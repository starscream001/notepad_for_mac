# GitHub-синхронизация · 0.9.1

«Сохранить» записывает выбранный локальный файл. Изменения заметок и проектов также автоматически восстанавливаются из локальной сессии. GitHub получает данные только по отдельной ручной команде синхронизации.

## Подключить

1. Настройки → GitHub → Войти через браузер. Подтвердить код на официальной странице GitHub.
2. При необходимости «Разрешить доступ GitHub»: установить Notepad Desktop в свой аккаунт с Contents read/write, Metadata read и Repository creation для создания хранилища. Выбирать только нужные репозитории.
3. Создать приватный репозиторий с README либо указать имя существующего приватного репозитория своего аккаунта. По умолчанию `notepad-notes`. Организации и публичные репозитории в этом выпуске не поддержаны.
4. Нажать отдельную кнопку GitHub/«Синхронизировать» и подтвердить отправку. Синхронизируются все открытые и закрытые локальные заметки и проекты, не только активная вкладка.
5. На другом устройстве войти в тот же аккаунт, указать то же имя и выполнить синхронизацию. Локальные заметки объединятся с загруженными.

Требуется доступ GitHub App к выбранному репозиторию. Ошибка прав/сети не должна стирать локальный текст. Авторизация может истечь: проверить вход и при необходимости войти заново. Автоматического фонового sync нет.

## Закрыть и удалить — разные действия

Крестик закрывает вкладку и оставляет заметку в боковой панели проекта. Нажатие по заметке открывает её снова. Закрытие сохраняет и несохранённый текст локальной сессии; внешний файл записывается по «Сохранить».

Кнопка корзины «Удалить заметку» запрашивает подтверждение и удаляет заметку из локального списка. Следующая синхронизация удаляет её из текущего облачного снимка; другие устройства применяют удаление при своей синхронизации. Внешний файл пользователя на диске не удаляется. Старые версии остаются в истории Git; это не очистка истории репозитория и не гарантированное стирание секретов.

Если удалённую заметку одновременно изменили на другом устройстве, изменённый текст сохраняется новой заметкой `(delete conflict)`. Если текст/метаданные изменились с двух сторон — сохраняются обе версии, одна с `(GitHub conflict)`. Ничего не затирается молча.

## Хранение и ограничения

Текст и названия проектов хранятся в `.notepad/snapshot.json` (schema 1) приватного репозитория. Это JSON-снимок, содержащий тексты, UUID и метки удаления. Локальные пути, токены, параметры окон и savedText не отправляются. Предел текущего sync: 300 заметок, 100 проектов, 1 MiB UTF-8 на заметку и 5 MiB на весь снимок. При превышении команда прекращается, исходные данные остаются локально.

Один sync создаёт один commit. Git tree строится от текущего дерева, остальные файлы репозитория сохраняются. Ветка обновляется только fast-forward, `force:false`; при одновременной записи GitHub отклоняет устаревшее изменение — повторить sync. Большие blobs/повреждённые snapshots не импортируются. Локальная base-версия лежит в github-sync.json пользовательского каталога, токены — в защищённом хранилище ОС.

Перед применением создаётся `session.before-sync.json`, перед явным удалением — `session.before-delete.json` в каталоге сессии. Не переносить эти файлы и github-sync.json в публичный репозиторий: в них есть локальные тексты. Если заметки менялись прямо во время native sync, они сохраняются, но могут потребовать следующего sync; интерфейс сообщает об этом.

Сквозного шифрования нет: private repo ограничивает доступ, но GitHub хранит содержимое. Доступ к своим внешним файлам редактор не выдаёт провайдеру.

## Проверки

Автотесты: shared merge + JavaScriptCore, Unicode, независимые правки, конфликт, удаление/изменение, tombstones, pinned Git tree, первый upload/download, повтор без лишнего commit, stale branch rejection, запрет public repo. Нативный UI: закрытие/восстановление заметки, сохранение текста, компактные контролы и настройки. Эти проверки не заменяют реальный двухустройственный QA с аккаунтом владельца и установку на Windows/Linux.
