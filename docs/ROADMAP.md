# Дорожная карта Notepad

Редактор должен оставаться лёгким, быстрым и полезным без аккаунта. Новые интеграции включаются по желанию, не запускают индексаторы и не требуют сервера разработчика. Это план, не список уже доступных функций. Обновлено 5 ноября 2026, при подготовке 0.8.

## Уточнение следующего шага

Владелец выбрал сначала **вход в GitHub через браузер**, отдельно от синхронизации. Код обоих клиентов подготовлен локально, ожидает регистрации OAuth App/Client ID и реального QA; опубликованная 0.8 не меняется. [Инструкция](GITHUB_SIGN_IN.md).

## Синхронизация: несколько подключений, свои данные

Предлагаемая модель: пользователь выбирает для проекта хранилище и папку/репозиторий. Например «Работа → корпоративный GitLab», «Личное → GitHub», «Дом → Nextcloud». Один проект сначала имеет один активный источник синхронизации; одновременное зеркало в несколько облаков отложить — оно усложняет конфликты. Не создавать единый аккаунт Notepad или общий репозиторий всех пользователей.

Общее ядро отвечает за UUID, очередь офлайн-изменений, удаление/переименование, ревизии, повтор после сбоя и трёхстороннее сравнение. Адаптеры отвечают за конкретный протокол, авторизацию и условную запись. Клиенты обращаются прямо в хранилище пользователя. Приватность и права задаёт владелец хранилища; приватный Git сам по себе не означает E2EE.

| Хранилище | Предлагаемый путь | Очерёдность и ограничения |
| --- | --- | --- |
| GitHub | Private repo, API, app/native authorization | Первый адаптер; минимум прав, выбор существующего/явное создание repo |
| GitLab.com / self-hosted | API, PKCE, свой URL | Следующий Git-адаптер; тестировать версии сервера, ограничения компаний и сертификаты |
| Bitbucket Cloud / Data Center | Отдельные адаптеры API/auth либо опциональный системный Git | Не считать Cloud и корпоративный сервер одинаковыми. Сначала подтвердить native flow без встроенного client secret |
| GitVerse | Публичный API и проверка OAuth возможностей | Под «гиверс» предполагается GitVerse; интеграция требует собственного прототипа, не копирования GitHub URL |
| Прочие Git-серверы, Gitea/Forgejo | Опциональный транспорт через установленный Git/его credential helper | Отдельный исследовательский этап; не тащить полный Git во все сборки по умолчанию |
| Nextcloud / ownCloud / NAS / личный сервер | WebDAV по HTTPS, ETag/If-Match, app password | Один адаптер покрывает несколько продуктов, но возможности конкретного сервера нужно проверять |
| Яндекс Диск | Сначала папка установленного клиента / WebDAV; затем REST при необходимости | Наличие и условия доступа проверять при реализации |
| Облако Mail | Папка клиента или WebDAV с паролем приложения | Без неофициального разбора веб-сайта; проверить ограничения тарифа/протокола |
| Google Drive | Папка клиента на desktop; отдельный Drive API на mobile | Выбрать видимую папку документов или закрытое appData, не смешивать их; отдельная OAuth настройка |
| OneDrive / Dropbox | Папка клиента, позже прямые API | Добавлять по реальному спросу и после проверки native auth |
| Apple iCloud Drive | На Mac выбранная папка; на iOS Files/iCloud document integration | Apple-адаптер, entitlement/container и document picker. Не обещать универсальный iCloud API для Android/Linux |
| SMB/NFS, другие личные хранилища | Выбранный/смонтированный каталог на desktop | Это файловый доступ; доступность сети и параллельная запись всё равно требуют защиты |

**Самый дешёвый первый облачный шаг — переносимый проект в выбранной папке.** Пользователь сам подключает её в своём облачном клиенте. Но нельзя просто перенести текущий session.json в облако: UUID/путь/служебное состояние и параллельная запись должны быть разделены. Файлы контента и manifest экспортируются в новый формат. На мобильных доступ к провайдерам файлов ограничен ОС и проверяется отдельно.

## Что именно сделать в 0.9

1. **Формат:** отдельный UTF-8 файл на вкладку, UUID вместо имени в идентичности, manifest проектов, версия схемы, импорт/экспорт и восстановление без аккаунта. Абсолютные локальные пути, токены и временные UI-настройки не отправляются.
2. **Ядро конфликтов до сети:** base/local/remote, diff и выбор обеих версий, tombstones для удаления, rename без потери UUID. Сначала автоматические тесты одновременных правок и падений.
3. **GitHub:** явное включение для выбранного проекта, безопасный native flow, выбор private repo, системное хранилище токенов, отмена/выход. Учитывать лимиты API; объединять изменения, не делать commit на каждое нажатие клавиши.
4. **Запись:** публиковать согласованное изменение файлов/manifest одним commit и защищать обновление ветки от гонок; при изменившемся remote получать свежую базу, сохранять конфликтные копии. Никогда не force-push пользовательскую ветку.
5. **Мобильный прототип:** общий CodeMirror/preview/формат и новая оболочка (кандидат Capacitor, подтвердить прототипом), отдельные iOS/Android адаптеры файлов и безопасного хранилища. Тот же sync core после его проверки на desktop.
6. **Критерий готовности:** два устройства, одновременная правка/удаление/переименование, длительный офлайн, отзыв токена, занятая сеть, закрытие приложения в середине sync. Ни одна свежая версия не затирается молча.

Git сохраняет историю и помогает объединить изменения, но не устраняет конфликты автоматически. Для WebDAV/обычных облаков Git-история не появляется сама: нужна локальная история/снимки и доступные ревизии провайдера. При отсутствии надёжной условной записи сначала сохранять обе копии; не обещать атомарность неподдерживаемого сервера. Подробности в [SYNC-0.9](SYNC-0.9.md).

## Телефоны и планшеты

- **Планшеты:** проекты слева, вкладки сверху, регулируемый split preview, внешняя клавиатура.
- **Телефоны:** компактный список проектов, редактор/просмотр переключаются, панель полезных клавиш над клавиатурой. Desktop-кнопки нельзя просто уменьшить.
- **Сначала локальная надёжность:** восстановление после выгрузки процесса, документы Files/Android SAF, Unicode и большие вставки, клавиатура и выделение. Затем sync.
- **Публикация отдельно:** Android beta и iPhone/iPad TestFlight после проверок на устройствах; магазины, аккаунты и подписи оформляет владелец. Прототип 0.9 не означает обещание одновременного stable во всех магазинах.

## Лицензия и доход: предложение, не изменение условий

**Сейчас MIT сохранена.** Она разрешает компаниям пользоваться и распространять приложение при соблюдении условий уведомления. Продажа «разрешения на коммерческое использование» уже опубликованного MIT-кода не даёт нового исключительного права. Удаление LICENSE или смена условий будущих выпусков не должны объявлять прежние MIT-копии запрещёнными.

| Модель | Польза | Издержки / ограничения |
| --- | --- | --- |
| MIT + донаты / добровольная покупка | Быстрый рост и простая установка в компаниях | Доход непредсказуем; донат не покупает SLA |
| **MIT core + платные отдельные Pro/Business модули** | Бесплатный редактор и понятная дополнительная ценность | Нужны отдельные условия/границы модулей, учёт сторонних прав |
| Платная поддержка / внедрение | Компания платит за настройку своего Git/NAS, исправления и согласованные сроки | Требуется время разработчика и реальный договор, не обещать круглосуточный SLA одному |
| Платная сборка в магазинах | Удобство покупки/обновления без нашего сервера | Аккаунты, комиссии, правила и доступность выплат |
| Бесплатно только некоммерчески | Прямое лицензирование будущего собственного кода | Это уже source-available, не Open Source по OSI; может затруднить распространение и вклад сообщества |

**Рекомендация:** оставить базовый редактор MIT, начать с добровольной поддержки и первых корпоративных заказов. Платными позже могут стать отдельные управляемые профили развёртывания, корпоративные шаблоны, подписанные offline policy-пакеты, интеграционное сопровождение. Обычные локальные файлы, экспорт и доступ к своим заметкам не блокировать. Не менять лицензию без отдельного решения владельца и проверки прав на включённый код/вклады.

Без сервера можно выдавать подписанный офлайн-ключ для действительно платного модуля или продавать через магазин. Это усложняет активацию/перенос/возврат и не даёт надёжного немедленного отзыва ключа. Подписка оправдана регулярной поддержкой/обновлениями, а не арендой собственного облака пользователя. Цену выбирать после первых запросов компаний; сейчас тарифы и платные ограничения не вводятся.

## Распространение и лёгкость

Приложение пока распространяется через **GitHub Releases**, не зарегистрировано в WinGet/Homebrew/Flathub. Команды скачивания через GitHub CLI и шаги подачи — [packaging](../packaging/README.md). Для центральных каталогов нужны устойчивые имена/URL, SHA256, метаданные и проверка установщиков. Текущая очистка установщиков через две версии может ломать старые pinned manifests: перед регистрацией решить хранение дольше или отдельный постоянный архив пакетов. Автоматически менять эту политику без решения владельца не нужно.

Измерять время холодного запуска, память с 1/120 вкладками и размер пакета на каждой ОС до/после крупных изменений. Mac остаётся нативным; Electron уже занимает заметно больше места, этого нельзя скрывать словом «лёгкий». Адаптеры загружать по запросу, сеть — по включённому sync, без фонового опроса всех провайдеров. AI, терминал, LSP, автолинтеры и маркетплейс не входят в ближайший обязательный объём. Форматирование JSON/SQL уже доступно по команде.
