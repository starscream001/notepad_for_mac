# Дорожная карта Notepad

Цель — быстрый, понятный редактор текста, кода и запросов на основных платформах. Разработчик — [Илья (starscream001)](https://github.com/starscream001). Все основные функции остаются бесплатными, исходники — MIT. Поддержка добровольная.

Это приоритеты, а не обещанные даты. Решения уточняются после реального тестирования и обратной связи через [Issues](https://github.com/starscream001/notepad_for_mac/issues).

## Сначала качество десктопа

- Пройти [платформенный чек-лист](PLATFORM_TESTING.md), исправить DPI, Wayland/X11, системные диалоги и права доступа.
- Проверить обновление поверх предыдущей версии на каждой ОС, затем добавить установку обновлений Windows/Linux с проверкой пакетов и восстановлением при ошибке.
- Подпись Windows и Apple Developer ID/notarization после оформления владельцем сертификатов.
- Расширить ARM64, дистрибутивы Linux и форматы пакетов по спросу.
- Сблизить список языков, недавние файлы, настройки, размер шрифта и формат сессий.

## Следующая полезная функциональность

1. Панель папки/проекта, быстрый переход к файлу, поиск по папке с предпросмотром замен.
2. Сравнение двух файлов, большие файлы, профили кодировок (в том числе Windows-1251), явное преобразование кодировки.
3. JSON: форматирование и валидация. SQL: форматирование с выбором диалекта. Команды форматирования всегда с Undo.
4. Улучшение Markdown: оглавление, экспорт HTML/PDF, локальные изображения с явным ограничением доступа.
5. Дополнение кода через LSP после определения нужных языков, управляемые расширения без произвольного доступа к системе.
6. Доступность: клавиатура, screen reader, размер текста и контраст на всех ОС.

## iPhone, iPad, Android и планшеты

Electron не превращается в мобильное приложение простой настройкой сборки. Для мобильных клиентов нужны отдельная оболочка и правила работы с файлами. Предлагаемый порядок:

- Сначала планшетный прототип: вкладки, внешний keyboard, split preview, локальные файлы.
- Затем адаптация телефона: редактор и просмотр переключаются, крупные кнопки, панель над клавиатурой, работа одной рукой.
- Исследовать Capacitor с общим редактором CodeMirror, а файловый доступ реализовать отдельными адаптерами iOS/Android. Сравнить с нативной оболочкой до закрепления архитектуры.
- Android: Storage Access Framework, разрешения на выбранные файлы, проверка сохранения при сворачивании и завершении процесса.
- iOS/iPadOS: Files/document picker, security-scoped URLs, внешняя клавиатура, восстановление после выгрузки.
- App Store/TestFlight и Google Play требуют аккаунтов владельца и отдельного процесса публикации.

Облачную синхронизацию добавлять только после устойчивого локального восстановления и решения конфликтов. До этого перенос — обычными файлами через системные средства.

## Как управлять развитием

Собирать предложения в Issues, выбирать небольшой набор для каждого релиза, поддерживать `main` и версионные теги. Каждый выпуск сопровождается CHANGELOG, README, описанием Release и готовыми пакетами. Перед сменой компьютера обновлять [HANDOFF](HANDOFF.md), чтобы продолжать с актуального состояния.

## Линтеры, текст и AI

Предлагаемый порядок реализации:

- **Офлайн база:** JSON-валидация и форматирование, диагностика Markdown, панель проблем. В CodeMirror есть [API для линтеров](https://codemirror.net/examples/lint/).
- **Код:** адаптер [LSP](https://microsoft.github.io/language-server-protocol/) для диагностик/подсказок и отдельные адаптеры ESLint, Ruff, SQLFluff. Инструменты устанавливаются явно; не выполнять неизвестные команды из документа.
- **Русский/английский текст:** подключение [LanguageTool HTTP server](https://dev.languagetool.org/http-server) на компьютере пользователя; удалённый сервис — отдельная настройка. Подчёркивание проблем, варианты исправления, собственный словарь.
- **AI:** [Ollama](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx) локально либо совместимый API провайдера по выбранному URL и ключу пользователя. Команды «Продолжить», «Улучшить выделение», «Объяснить SQL», «Предложить исправление».
- **Применение:** показать diff до замены, проверять, что документ не изменился за время запроса, применять правку одной Undo-транзакцией; поддержать отмену запроса и streaming.
- **Контекст:** по умолчанию только выделение, отправка по кнопке; весь файл/проект подключается явно. Ключи — в системном защищённом хранилище, не в репозитории и не в session.json.

Расширения VS Code не работают в CodeMirror напрямую. Сначала нужны собственные адаптеры и небольшой API: команды, диагностики, форматтеры, чтение выделения и предложение правок. Затем — manifest с версиями и разрешениями, изоляция процессов, установка/отключение расширений. Маркетплейс имеет смысл после стабилизации API. Лицензии каждого внешнего компонента проверять до включения в дистрибутив.

Эти возможности пока **запланированы**, а не включены в 0.6. Мобильный прототип не означает готовую публикацию во всех магазинах: iOS/Android требуют отдельных проверок, аккаунтов и оформления выпуска.

## Уточнение приоритетов после 0.7.0

Владелец выбрал лёгкий редактор без лишней суеты. Ручное JSON/SQL форматирование уже входит в 0.7.0. Ближайший кандидат — минимальные проекты: открыть папку, дерево по мере раскрытия, скрываемая панель, восстановление вкладок. Git, терминал, фоновые индексаторы, линтеры/LSP и AI не включать автоматически; прежние номера этапов остаются ориентиром, а не обязательным объёмом следующего выпуска. Мобильные/планшетные версии требуют отдельного прототипа и остаются в плане.
