# 0.9 — мобильный прототип, авторизация и синхронизация без нашего сервера

Решение владельца: реализовывать после 0.8, **не включать в 0.8**. Разработчик не содержит собственный облачный сервер. Все запросы выполняются клиентом напрямую к выбранному провайдеру. По умолчанию синхронизация выключена; локальная работа и восстановление не требуют аккаунта.

## Этапы

1. Зафиксировать переносимый формат проектов/вкладок и устойчивые UUID, экспорт/импорт, журнал локальных изменений.
2. Мобильный прототип Android и iPhone/iPad: список проектов/вкладок, редактор, офлайн-сохранение; на планшете боковая панель. Не обещать автоматический перенос AppKit/Electron на телефоны: мобильному клиенту нужна отдельная оболочка и проверки.
3. Авторизация и первый клиентский адаптер GitHub. Регистрация OAuth/GitHub App, публичный native client, безопасный PKCE/поддерживаемый провайдером flow. Секрет приложения нельзя встраивать в бинарник; требования конкретного grant проверить по документации перед реализацией. Владелец регистрирует приложение, пользователь сам подтверждает доступ.
4. Пользователь выбирает существующий либо явно создаёт **приватный репозиторий**, включает синхронизацию; права — минимально необходимые. Токены — Keychain/Credential Manager/Keystore, не JSON сессии, не git.
5. История Git и конфликты: отдельный файл на вкладку с UUID, manifest проектов отдельно, локальный base commit/blob SHA. Изменения файлов и manifest объединяются в commit, обновление ветки защищено от гонок, без force-push. Условная запись по актуальному SHA, при 409/расхождении — получить удалённую версию и сравнить base/local/remote. Не перезаписывать свежие данные молча. Сохранить конфликтные копии и показать diff/выбор/ручное объединение. Отдельно обработать удаление и переименование.
6. Проверки: два устройства одновременно правят одну вкладку; офлайн-период; отзыв токена; удаление репозитория; новый компьютер; сбой посреди нескольких записей; отмена синхронизации и локальное восстановление. История Git помогает вернуть версии, но не решает конфликты автоматически.

## Другие адаптеры

Полный порядок GitLab/Bitbucket/GitVerse, Яндекс/Google/Mail, iCloud и NAS, а также мобильных beta и монетизации — в [ROADMAP](ROADMAP.md). Все эти интеграции пока планируются. У проекта сначала один источник синхронизации; не зеркалировать его сразу во все облака.


- **Папка синхронизации:** пользователь выбирает локальную папку своего облачного клиента; на десктопе проще всего. На мобильных — системные document providers и ограничения sandbox; проверить поддержку отдельно.
- **WebDAV:** Nextcloud/NAS пользователя, прямой HTTPS, учётные данные в системном хранилище, ETag/If-Match для конфликтов.
- **Dropbox/OneDrive:** отдельные OAuth-native адаптеры, если есть спрос. Не обещать все интеграции в первом 0.9.

Приватный репозиторий не равен сквозному шифрованию: GitHub хранит содержимое. Если добавлять E2EE, формат, управление ключами и восстановление согласовать отдельно; текстовый Git-diff на сервере при этом теряется. Никаких встроенных общих токенов, обхода правил провайдеров или скрытой отправки заметок.

Первый прототип ещё не означает публикацию во всех мобильных магазинах. Финальный набор 0.9 выбирать после проверки 0.8 на Windows/Linux.
